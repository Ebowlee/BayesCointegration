## 方案B: 添加滚动协整检查 (Rolling Cointegration Check)

**提出时间**: 2025-02-10
**当前状态**: 暂不实施,保留方案
**优先级**: 中等

### 问题背景

**当前机制的局限**:
- 协整检测: 每月MonthStart全局重新检测 (252天lookback, p-value < 0.01)
- 问题: 持仓配对可能在月中协整关系破裂,但要等到下月才能检测到
- 风险: 30天滞后期内可能继续交易已失效的配对,增加亏损

**实际案例** (2023-09-20 to 2024-09-21回测):
- 协整破裂率: 37.5% (6/16 pairs)
- 平均亏损: -0.3% (PAIR_BREAK exit)
- 说明: 当前机制下仍有较高比例配对因协整失效而止损

### 方案详情: 每周滚动检查

**核心思路**: 对**持仓配对**进行高频(每周)协整复查,使用**90天滚动窗口**早期发现协整破裂

#### 实现架构

```python
# 新增模块: src/risk/RollingCointegrationMonitor.py

class RollingCointegrationMonitor:
    """
    持仓配对滚动协整监控

    设计原则:
    - 仅检测持仓配对 (减少计算开销)
    - 每周执行 (周一 Schedule.Weekly)
    - 90天滚动窗口 (vs 252天月检)
    - 独立于月度全局检测

    触发条件:
    - Engle-Granger p-value >= 0.05 (比选择时的0.01宽松)

    触发动作:
    - 标记pair.cointegration_weak = True
    - 生成CloseIntent(reason='COINTEGRATION_ALERT')
    - 激活60天冷却期
    """

    def __init__(self, algorithm, config: dict):
        """
        Args:
            config: {
                'enabled': True,
                'check_frequency': 'Weekly',  # Weekly / Daily
                'lookback_days': 90,          # 滚动窗口
                'p_value_threshold': 0.05,    # 触发阈值
                'cooldown_days': 60           # 平仓后冷却期
            }
        """
        self.algorithm = algorithm
        self.config = config
        self.lookback_days = config.get('lookback_days', 90)
        self.p_value_threshold = config.get('p_value_threshold', 0.05)

    def check_held_pairs(self) -> Dict[str, float]:
        """
        检查所有持仓配对的协整状态

        Returns:
            Dict[pair_id, p_value]: 触发预警的配对及其p-value
        """
        alerts = {}
        held_pairs = self.algorithm.pairs_manager.get_pairs_with_position()

        for pair in held_pairs.values():
            # 1. 获取90天历史数据
            history1 = self.algorithm.History(pair.symbol1, self.lookback_days, Resolution.Daily)
            history2 = self.algorithm.History(pair.symbol2, self.lookback_days, Resolution.Daily)

            if history1.empty or history2.empty:
                continue

            # 2. 执行协整检测 (复用CointegrationAnalyzer)
            try:
                from statsmodels.tsa.stattools import coint
                _, p_value, _ = coint(history1['close'], history2['close'])

                # 3. 判断是否失效
                if p_value >= self.p_value_threshold:
                    alerts[pair.pair_id] = p_value
                    self.algorithm.Debug(
                        f"[滚动协整] {pair.pair_id} 预警: "
                        f"p-value={p_value:.4f} >= {self.p_value_threshold}"
                    )

            except Exception as e:
                self.algorithm.Debug(f"[滚动协整] {pair.pair_id} 检测失败: {str(e)}")

        return alerts
```

#### main.py集成点

```python
# main.py Initialize方法

# 初始化滚动协整监控
if self.config.rolling_cointegration['enabled']:
    from src.risk.RollingCointegrationMonitor import RollingCointegrationMonitor
    self.rolling_coint_monitor = RollingCointegrationMonitor(
        self,
        self.config.rolling_cointegration
    )

    # 注册定时任务 (每周一09:35执行)
    self.Schedule.On(
        self.DateRules.Every(DayOfWeek.Monday),
        self.TimeRules.AfterMarketOpen('SPY', 5),
        self._check_rolling_cointegration
    )

def _check_rolling_cointegration(self):
    """定时回调: 检查持仓配对协整状态"""
    if not hasattr(self, 'rolling_coint_monitor'):
        return

    # 1. 执行检查
    alerts = self.rolling_coint_monitor.check_held_pairs()

    if not alerts:
        self.Debug("[滚动协整] 所有持仓配对协整正常", 2)
        return

    # 2. 对预警配对生成CloseIntent
    for pair_id, p_value in alerts.items():
        pair = self.pairs_manager.get_pair_by_id(pair_id)
        if not pair:
            continue

        # 检查订单锁
        if self.tickets_manager.is_pair_locked(pair_id):
            continue

        # 生成平仓意图
        intent = pair.get_close_intent(reason='COINTEGRATION_ALERT')
        if intent:
            tickets = self.order_executor.execute_close(intent)
            if tickets:
                self.tickets_manager.register_tickets(
                    pair_id, tickets, 'CLOSE', reason='COINTEGRATION_ALERT'
                )
                self.Debug(
                    f"[滚动协整] {pair_id} 预警平仓: p-value={p_value:.4f}",
                    1
                )
```

### 预期效果

**收益**:
1. **早期预警**: 从30天滞后缩短至7天滞后 (每周检查)
2. **减少亏损**: 协整破裂配对提前平仓,避免继续亏损
3. **灵活窗口**: 90天窗口比252天更敏感,捕捉短期变化

**风险**:
1. **计算开销**: 每周需对所有持仓配对请求90天历史数据
   - 假设平均5个持仓 × 2 symbols × 90 days = 900个数据点
   - 可接受开销 (vs 月度全universe检测)
2. **误报风险**: 90天窗口较短,可能将临时波动误判为协整破裂
   - 缓解措施: p-value阈值0.05比选择时0.01宽松
3. **过度交易**: 可能增加平仓频率,降低持仓时间
   - 缓解措施: 60天冷却期防止频繁进出

### 实施工作量

- **代码量**: ~100行 (RollingCointegrationMonitor.py + main.py集成)
- **测试**: 需回测验证误报率和收益提升
- **配置**: 需调优lookback_days和p_value_threshold参数

### 对比: 方案A vs 方案B vs 方案C

| 维度 | 方案A: 保持现状 | **方案B: 滚动协整** | 方案C: 轻量预警 |
|------|----------------|-------------------|----------------|
| 检测滞后 | 30天 | 7天 | 1天 |
| 计算开销 | 低 (月度) | 中等 (周度) | 低 (日度统计) |
| 准确性 | 高 (252天) | 中 (90天) | 低 (无统计检验) |
| 实施成本 | 0 | 100行 | 50行 |
| 误报风险 | 无 | 中等 | 高 |

**推荐**: 先实施方案B并回测验证效果,如果误报率过高再考虑方案A或C

## 方案C: VIX期限结构倒挂检测 (VIX Term Structure Inversion)

**提出时间**: 2025-02-10
**当前状态**: 暂不实施,保留方案
**优先级**: 中等

### 问题背景

**当前VIX机制的局限**:
- 现有过滤: 全局VIX检测 (VIX > 30时禁止开仓)
- 问题: 单一VIX阈值无法区分"正常波动"和"市场恐慌升级"
- 遗漏信号: VIX期限结构倒挂 (VIX9D > VIX) 是流动性危机的经典预警

**期限结构理论**:
- **正常状态**: 远期波动率 > 近期波动率 (VIX > VIX9D)
  - 市场预期波动逐渐平息,期权卖方愿意以较低溢价承担远期风险
- **倒挂状态**: 近期波动率 > 远期波动率 (VIX9D > VIX)
  - 市场预期近期风险激增,反映流动性枯竭或系统性压力
  - 历史案例: 2008金融危机, 2020新冠暴跌, 2022俄乌冲突

**实际案例** (2023-09-20 to 2024-09-21回测):
- VIX检测触发: 3次 (全局停止开仓)
- 期限结构倒挂: 未监控 (现有机制缺失)
- 潜在改进: 倒挂检测可能提前1-3天捕捉恐慌升级

### 方案详情: VIX9D/VIX比率监控

**核心思路**: 监控**VIX9D与VIX的比率**,当近期恐慌显著高于远期时停止开仓

#### 实现架构

```python
# 新增模块: src/risk/VIXTermStructureMonitor.py

class VIXTermStructureMonitor:
    """
    VIX期限结构倒挂监控

    设计原则:
    - 监控VIX9D/VIX比率 (9天期/30天期)
    - 每日OnData检查 (开仓前置条件)
    - 独立于全局VIX阈值检测

    触发条件:
    - VIX9D / VIX >= 1.10 (近期恐慌溢价≥10%)

    触发动作:
    - 返回市场状态标记: NORMAL / INVERSION
    - ExecutionManager据此决定是否允许开仓
    - 不影响平仓逻辑
    """

    def __init__(self, algorithm, config: dict):
        """
        Args:
            config: {
                'enabled': True,
                'inversion_threshold': 1.10,  # VIX9D/VIX比率阈值
                'use_strict_mode': False      # 严格模式: 1.05即触发
            }
        """
        self.algorithm = algorithm
        self.enabled = config.get('enabled', True)
        self.inversion_threshold = config.get('inversion_threshold', 1.10)

        # 添加VIX和VIX9D指标订阅
        if self.enabled:
            self.vix_symbol = self.algorithm.AddIndex("VIX", Resolution.Daily).Symbol
            self.vix9d_symbol = self.algorithm.AddIndex("VIX9D", Resolution.Daily).Symbol

    def check_term_structure(self) -> Tuple[str, float]:
        """
        检查VIX期限结构状态

        Returns:
            (status, ratio):
            - status: 'NORMAL' 或 'INVERSION'
            - ratio: VIX9D/VIX比率 (用于日志)
        """
        if not self.enabled:
            return 'NORMAL', 0.0

        # 1. 获取当前VIX和VIX9D价格
        try:
            vix = self.algorithm.Securities[self.vix_symbol].Price
            vix9d = self.algorithm.Securities[self.vix9d_symbol].Price

            if vix <= 0 or vix9d <= 0:
                return 'NORMAL', 0.0  # 数据异常,保守允许交易

            # 2. 计算比率
            ratio = vix9d / vix

            # 3. 判断是否倒挂
            if ratio >= self.inversion_threshold:
                self.algorithm.Debug(
                    f"[VIX期限结构] 倒挂检测: VIX9D={vix9d:.2f}, VIX={vix:.2f}, "
                    f"比率={ratio:.3f} >= {self.inversion_threshold}",
                    1
                )
                return 'INVERSION', ratio

            return 'NORMAL', ratio

        except Exception as e:
            self.algorithm.Debug(f"[VIX期限结构] 检测失败: {str(e)}", 2)
            return 'NORMAL', 0.0  # 异常时保守允许交易
```

### 预期效果

**收益**:
1. **早期预警**: 倒挂信号通常领先VIX>30阈值1-3天
   - 2020-03: VIX倒挂出现于VIX=28时,次日VIX飙至40+
2. **精准过滤**: 区分"正常波动"(VIX=25但无倒挂)和"恐慌升级"(VIX=25且倒挂)
3. **理论基础强**: 期限结构倒挂是金融学教科书级别的风险信号

**风险**:
1. **数据依赖**: 需要QuantConnect支持VIX9D数据 (需验证可用性)
   - 替代方案: 使用VVIX (VIX的波动率) 或VIX1D/VIX3M比率
2. **误报风险**: 非危机时期偶发倒挂 (如大选前夜)
   - 缓解措施: 1.10阈值比1.05更保守,减少误报
3. **开仓机会减少**: 可能错过部分高波动但非危机的交易机会
   - 缓解措施: 仅影响开仓,不影响平仓,保护现有持仓

### 实施工作量

- **代码量**: ~80行 (VIXTermStructureMonitor.py + main.py集成)
- **数据验证**: 需确认QuantConnect VIX9D数据可用性
- **回测**: 需历史回测验证倒挂检测的有效性和误报率
