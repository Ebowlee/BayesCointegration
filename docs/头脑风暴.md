# Brainstorming & Future Ideas (头脑风暴)

## 开仓时行业集中度检查 (Opening-Time Concentration Check)

*问题*: 配额分配是"月度批发"，开仓是"日常零售"。即使配额分配时某行业没超标，密集开仓后仍可能导致集中度超标。

*场景示例*:
- 行业A当前集中度35%，有3个配对A1、A2、A3排队开仓（每个计划投资5%）
- 如果不检查，全部开仓后集中度 = (35%+15%) / (100%+15%) ≈ 43% > 40% 超标

### 方案: 预测式集中度检查
*   **核心公式**:
    ```
    预测集中度 = (该行业当前已投 + 本次计划投资) / (全部已投 + 本次计划投资)

    如果 预测集中度 > 阈值(40%):
        跳过该配对，机会给下一个
    否则:
        开仓，更新动态基线
    ```
*   **实现位置**: `PairsManager.allocate_margin_to_candidates()`
*   **关键设计点**:
    1. **动态基线更新**: 使用 `industry_planned_investment` 字典追踪本轮已分配给各行业的资金
    2. **预测公式**:
       - 分子 = 该行业当前已投 + 本轮已计划 + 本次计划
       - 分母 = 全部当前已投 + 本轮所有已计划 + 本次计划
    3. **日志输出**: 跳过时输出详细原因，便于调试

*   **验证场景**:
    - **场景1: 单行业多配对**
      - 行业A当前35%，A1(5%)、A2(5%)、A3(5%)排队
      - A1: (35+5)/(100+5) = 38.1% < 40% ✓ → 开仓
      - A2: (35+5+5)/(100+5+5) = 40.9% > 40% ✗ → 跳过
      - 结果: 只开仓A1
    - **场景2: 多行业交错**
      - 行业A当前35%，行业B当前30%
      - A1(5%)、B1(5%)、A2(5%)排队
      - 分母随开仓增加，A2可能仍可开仓

*暂缓原因*: 待进一步验证实际回测中是否频繁触发集中度超标问题。

## PairSelector 滞后性优化 (Lag Mitigation)
*问题*: 基于 252 天历史数据的评分指标 (Half-life, Zero-crossing) 具有滞后性，可能无法反映当前市场状态。

### 方案 A: 近期权重加权 (Recency Weighting)
*   **思路**: 类似于 Industry Quota 的 Rolling Window，对计算指标时引入时间衰减权重。
*   **实现**:
    *   在计算 Zero-crossing 时，给予最近 3 个月的穿越更高的权重。
    *   在贝叶斯建模中，虽然已经用了 Informed Prior (上月后验)，但可以进一步缩短 Lookback Window (例如 120 天) 用于敏感性测试。

### 方案 B: 波动率状态过滤 (Volatility Regime Filter)
*   **思路**: 历史表现好可能是在低波动环境下，如果当前 VIX 飙升，历史参数可能失效。
*   **实现**:
    *   计算 `Current Volatility / Historical Volatility` 比率。
    *   如果比率 > 1.5 (当前波动剧烈)，则对 Quality Score 进行惩罚 (降分)。

### 方案 C: 早期止损机制 (Fast Failure) - 推荐实施
*   **核心理念**: 承认选股会有滞后，通过执行层的快速止损来弥补。
*   **具体实现**:
    1.  **时间止损 (Time Stop)**:
        *   逻辑: 如果持仓时间超过理论回归周期的 3 倍仍未盈利，说明均值回归失效。
        *   公式: `HoldDays > 3 * HalfLife` AND `PnL < 0` -> 强制平仓。
    2.  **僵尸止损 (Stagnation Stop)**:
        *   逻辑: 开仓后短期内 (如 5 天) Spread 没有任何回归迹象 (甚至恶化)。
        *   公式: `HoldDays > 5` AND `abs(CurrentZ) > 0.9 * abs(EntryZ)` -> 强制平仓。
        *   意义: 避免资金被无效的"死鱼"配对占用。

### 方案 D: 结构性断裂检测 (Structural Break Detection)
*   **思路**: 检测是否发生了协整关系的根本性破坏。
*   **实现**:
    *   使用 Chow Test 或简单的 Rolling Variance Ratio。
    *   如果检测到断裂，直接将 Quality Score 置为 0。
