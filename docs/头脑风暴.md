# Brainstorming & Future Ideas (头脑风暴)

1. Cointegration Analyzer Optimization (协整初筛优化)
    Current Issue: Sorting Bias (排序偏差)
        现状: 行业内只取 DollarVolume 前 40 名。
        缺点: 错过中小市值股票的套利机会，且头部资产竞争激烈，Alpha 空间小。

    Idea A: Head + Tail Strategy (龙头+黑马)
        逻辑: 取成交额前 20 名（保底流动性） + 从剩下的股票中随机抽取 20 名。
        优势: 既保留核心资产稳定性，又引入中小盘的高波动/低效定价机会。
        适用: 资金量 < 100万美金，追求更高 Alpha。

    Idea B: Rolling Window (轮询机制)
        逻辑: 按月轮询行业内的股票池（如第1月测1-40名，第2月测41-80名...）。
        优势: 长期运行可覆盖全行业，不遗漏任何角落。
        适用: 长期策略，追求全面覆盖。

    Idea C: Relaxed P-Value Threshold (放宽P值阈值)
        现状: pvalue < 0.01 (99% 置信度)。
        建议: 放宽至 0.05。
        理由: 初筛过严可能漏掉机会，后续贝叶斯模型有能力进行二次过滤。

## 2. PairSelector 滞后性优化 (Lag Mitigation)
*问题*: 基于 252 天历史数据的评分指标 (Half-life, Zero-crossing) 具有滞后性，可能无法反映当前市场状态。

### 方案 A: 近期权重加权 (Recency Weighting)
*   **思路**: 类似于 Industry Quota 的 Rolling Window，对计算指标时引入时间衰减权重。
*   **实现**:
    *   在计算 Zero-crossing 时，给予最近 3 个月的穿越更高的权重。
    *   在贝叶斯建模中，虽然已经用了 Informed Prior (上月后验)，但可以进一步缩短 Lookback Window (例如 120 天) 用于敏感性测试。

### 方案 B: 波动率状态过滤 (Volatility Regime Filter)
*   **思路**: 历史表现好可能是在低波动环境下，如果当前 VIX 飙升，历史参数可能失效。
*   **实现**:
    *   计算 `Current Volatility / Historical Volatility` 比率。
    *   如果比率 > 1.5 (当前波动剧烈)，则对 Quality Score 进行惩罚 (降分)。

### 方案 C: 早期止损机制 (Fast Failure) - 推荐实施
*   **核心理念**: 承认选股会有滞后，通过执行层的快速止损来弥补。
*   **具体实现**:
    1.  **时间止损 (Time Stop)**:
        *   逻辑: 如果持仓时间超过理论回归周期的 3 倍仍未盈利，说明均值回归失效。
        *   公式: `HoldDays > 3 * HalfLife` AND `PnL < 0` -> 强制平仓。
    2.  **僵尸止损 (Stagnation Stop)**:
        *   逻辑: 开仓后短期内 (如 5 天) Spread 没有任何回归迹象 (甚至恶化)。
        *   公式: `HoldDays > 5` AND `abs(CurrentZ) > 0.9 * abs(EntryZ)` -> 强制平仓。
        *   意义: 避免资金被无效的“死鱼”配对占用。

### 方案 D: 结构性断裂检测 (Structural Break Detection)
*   **思路**: 检测是否发生了协整关系的根本性破坏。
*   **实现**:
    *   使用 Chow Test 或简单的 Rolling Variance Ratio。
    *   如果检测到断裂，直接将 Quality Score 置为 0。

## 3. Pairs Class Refactoring (Pairs类重构)
*问题*: `Pairs` 类承担了过多的状态管理职责，且历史数据清理机制缺失。

### 方案 A: 引入状态对象 (State Object Pattern)
*   **现状**: `Pairs` 类中散落着 `tracked_qty`, `entry_price`, `pair_hwm` 等十几个独立变量，平仓时需手动重置，容易遗漏。
*   **建议**: 创建 `PairPosition` 数据类封装所有持仓相关状态。
    *   开仓时: `self.position = PairPosition(...)`
    *   平仓时: `self.position = None` (自动销毁所有状态，彻底杜绝脏数据残留)。

### 方案 B: 历史数据自动清理 (History Cleanup)
*   **现状**: `trade_history` 列表无限增长，长期运行会消耗大量内存。
*   **建议**: 在 `_update_trade_stats` 中增加轻量级清理逻辑。
    *   策略: 仅保留最近 365 天的记录 (足够覆盖 180 天的 Rolling Window)。
    *   实现: `self.trade_history = [t for t in self.trade_history if t[0] >= cutoff_time]`。
